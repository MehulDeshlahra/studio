## Editing that wins
**Core pattern:** show *evidence* aligned to narration, with fast alternation between talk/graphics/screens.

### A) Evidence-first overlays (screens/UI/news/diagrams)
- Apology/news evidence + highlight syncing: split screen + email screenshot with text highlighting (biAwtOHBve8 4.05x).
- Real diagram kept as “map”: architectural diagram stays on screen; icons highlight in sync (551lh10g_go 4.4x, S4tLX3kq4Ik 3.74x).
- Real UI repository/screenshot transitions: GitHub repo + zoom-ins + side-by-side screenshots (zsah85KcyTQ 7.08x).

**Do this:**
- Add a yellow/bright highlight only on **1–2 key words** at the moment they’re spoken (biAwtOHBve8 4.05x, vzO_Tc9AQ10 4.57x, kCD532ylVGc 4.11x, zsah85KcyTQ 7.08x).
- For diagrams, keep a stable “backbone” background and only animate the relevant parts (551lh10g_go 4.4x, S4tLX3kq4Ik 3.74x).

### B) Recurring object / visual anchor
- Recurring 3D home object: King Tut tomb model evolving through the short (kCD532ylVGc 4.11x).
- Recurring “phone/product” anchor for comparisons: two phones shown side-by-side (otwhI0lg72c 5.65x), remote shown repeatedly (dX_fna-Bx4E 5.0x).

**Rule:** pick one anchor (object/diagram/terminal) and return to it multiple times (kCD532ylVGc 4.11x, dX_fna-Bx4E 5.0x, otwhI0lg72c 5.65x).

### C) Split-screen / PiP for continuity
- Creator bottom + graphics/top split: (2KmY_lSQi10 4.07x, vzO_Tc9AQ10 4.57x, S4tLX3kq4Ik 3.74x).
- PiP + screen recording kept readable: (By default for app-style winners is split/PiP; avoid ad-only vibe—see flops fHU4neQCpkc 0.18x, ByvdT-CDfoE 0.15x).

### D) Structured list editing (countdowns/stacking)
- Countdown structure: numbers (2,3,5) for list pacing (vzO_Tc9AQ10 4.57x).
- Stacking “loopable” narrative: year counter + logo stacking (aXcuz6fn8_w 3.47x).

## Sound
- **Music usage:** many winners use a subtle tech/upbeat bed; some top performers use **no music**.
  - Music under voice: subtle upbeat/tech bed (2KmY_lSQi10 4.07x, dX_fna-Bx4E 5.0x, zsah85KcyTQ 7.08x shows subtle bed but no SFX) and suspense bed (biAwtOHBve8 4.05x).
  - **No music** for pure diagram short: ByteByteGo (551lh10g_go 4.4x).

- **SFX:** use only where it strengthens transitions/actions.
  - Subtle whoosh/click for transitions (biAwtOHBve8 4.05x, kCD532ylVGc 4.11x).
  - Action/prop emphasis: confetti/cheer on reveal (EQBLRjWmNBk 36x), slap/whoosh/click on gadget actions (dX_fna-Bx4E 5.0x).

- **Voice clarity:** fast, energetic narration keeps momentum (otwhI0lg72c 5.65x, dX_fna-Bx4E 5.0x, vzO_Tc9AQ10 4.57x).

- 3D medical “suction/squelch” style: (EHhqfU1kXxQ 0.13x).

5) **Repetitive loop without escalation**
- “drill→hang→break ×5” predictability: (GycFYrtbVqw 0.14x).

6) **No music + no SFX + flat delivery**
- (GycFYrtbVqw 0.14x explicitly: no background music and no music bed; lacks the action/sfx richness seen in winners like dX_fna-Bx4E 5.0x).

## Never
- Glows/neon, particle bursts, crossfades between scenes, bouncy easing, text or labels in the corners, HUD counters, stat slides, slide/deck layouts, stock-template looks, idle floating/breathing loops, dead time >1 s without a reason, anything appearing before it is spoken, invented facts or numbers, mock UI where a real screenshot exists. (No evidence contradicts; winners rely on hard cuts/anchored evidence/screens (biAwtOHBve8 4.05x, zsah85KcyTQ 7.08x, 551lh10g_go 4.4x) while flops show missing/weak structure (GycFYrtbVqw 0.14x, ByvdT-CDfoE 0.15x, fHU4neQCpkc 0.18x)).
